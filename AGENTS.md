## What this is

**Overheard: Bird Journal** is an iPhone app that listens during walks and identifies birds by sound **on the device**, using BirdNET through Core ML. It draws each walk as a hand-drawn field-journal page, and friends follow each other's walks.
- Free, for friends and family. No monetization.
- Distributed through TestFlight first.
- Domain: `overheardbirds.app`.

## Stack

- **iOS** (`apps/ios`): SwiftUI, iOS 17+, **Swift 6** language mode (strict concurrency).
  - The project is generated by XcodeGen from `project.yml`.
  - Detection logic lives in the local Swift package **`apps/ios/OverheardKit`** (iOS + macOS), shared by the app and the Mac eval tool. Put pipeline logic there, not in the app target.
- **Models** (`ml/models/coreml`, in **Git LFS**): BirdNET v2.4 audio and location models as Core ML (FP32), `labels.txt`, and `species.json`. A fresh clone builds without Python.
- **ML scripts** (`ml/`): Python 3.11 venv with TensorFlow 2.15 and coremltools 9. Only needed to regenerate the models or species catalog, or to fetch eval data.
- **CI** (`.github/workflows/ci.yml`): OverheardKit unit tests, an unsigned iOS build, and Ruff.
- **Backend** (planned): TypeScript on Cloudflare Workers.
  - **Hono** for the API and **Drizzle** for D1.
  - R2 for images and Queues for art jobs. Terraform for infrastructure. pnpm workspaces, no Turborepo.
- **Auth** (planned): Sign in with Apple only.
- **Observability** (planned): traces go to Honeycomb (OTLP from Workers), and all errors go to Sentry.
- **Bird art:** `gemini-3-pro-image` through the Batch API, drawn on flat white, then cut out to a transparent PNG.

## Quick start

```sh
git lfs install --local && git lfs pull   # model files (~100 MB)
nvm use                                   # Node 24 from .nvmrc (art scripts now, backend later)

# iOS
cd apps/ios
cp Config/Local.xcconfig.example Config/Local.xcconfig   # then set DEVELOPMENT_TEAM (see apps/ios/README.md)
xcodegen                                  # regenerate after editing project.yml
open Overheard.xcodeproj                  # ⌘R onto a connected iPhone
cd ../..

# Tests, plus a compile check without signing (what CI runs)
swift test --package-path apps/ios/OverheardKit
xcodebuild -project apps/ios/Overheard.xcodeproj -scheme Overheard \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build

# Detection eval (the app's Swift pipeline, on the Mac)
ml/.venv/bin/python -I ml/eval/fetch.py   # data; birds need XENO_CANTO_API_KEY in .env
ml/.venv/bin/python -I ml/eval/fetch_rare.py   # rare-bird set (unlikely-here birds)
swift run -c release --package-path apps/ios/OverheardKit overheard-eval --verbose   # ~3.5 min; --no-mix / --hop 3 for quicker runs

# Regenerating the models (rarely; full steps in ml/README.md)
cd ml && uv venv --python 3.11 .venv && uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python -I convert.py            # → BirdNETAudio + BirdNETMeta .mlpackage, labels.txt
.venv/bin/python -I bird_labels.py        # → species.json (eBird codes, bird/non-bird)
.venv/bin/python -I verify.py             # Core ML vs TensorFlow, both models

# Image model trial (needs GEMINI_API_KEY / OPENAI_API_KEY in .env)
node --env-file=.env art/model-comparison/run.mjs

# Bird art (needs GEMINI_API_KEY; full steps in art/birds/README.md)
node --env-file=.env art/birds/generate.mjs                   # draw missing birds as one batch
swift art/birds/cutout.swift art/birds/out/raw art/birds/cutouts   # cut out to transparent PNGs
node art/birds/review.mjs && open art/birds/out/review.html   # check them
```

## Conventions

- **Secrets:** keep them in `.env` (gitignored). Never commit keys, and never print them in logs or output.
- **Species IDs:** store and sync species by **`Species.code`** (an eBird code like `norcar`). Never store BirdNET output indices; they change between model versions.
- **Licensed files:** the BirdNET models in `ml/models/coreml` are CC BY-NC-SA 4.0 adaptations. Keep the attribution in `ml/models/coreml/README.md` and the app's Credits. Raw BirdNET downloads stay gitignored.
- **Xcode project:** don't edit or commit `Overheard.xcodeproj`. Change `apps/ios/project.yml` and run `xcodegen`.
- **Signing:** your team ID goes in `apps/ios/Config/Local.xcconfig` (gitignored), never in `project.yml`.
- **Concurrency:** Swift 6 strict mode everywhere. Models and session state live in the `ListeningPipeline` actor. Don't use `DispatchQueue.main.sync`, and don't capture tap buffers past their callback.
- **Python:** run it with `.venv/bin/python -I`. Python on this machine resolves through pyenv and conda, so use the venv. `.vscode/settings.json` points the editor and Ruff at `ml/.venv`, and turns off Flake8 and Pylint. `pyrightconfig.json` points basedpyright at `ml/.venv`.
- **Editor (Swift):** `xcode-build-server config -project apps/ios/Overheard.xcodeproj -scheme Overheard` writes `buildServer.json` (gitignored). Without it, VS Code checks app files as macOS code and flags iOS-only APIs like `AVAudioSession`.
- **UI:** tokens and fonts come from `docs/design.md`. No emoji, and touch targets are at least 44 pt.
- **Rarity:** use `HeardBird.commonness` (`.unusual` → the naturalist flourish); never recompute it from model output.
- **Bird size:** on Listen and Journal pages, a bird's size means call count and nothing else. A call is one song or burst of calls: detections less than 2.5 s apart merge. Rarity is shown with the red-ink "naturalist flourish".
- **Location privacy:** blur shared points to a ~500 m grid, trim ~200 m from the start and end of routes, and show no location for sensitive species. Detection only needs approximate location.
- **IDs:** the phone generates walk and detection IDs, which makes uploads safe to retry.
- **Tests:** detection and app logic go in `OverheardKit` as plain, model-free types (like `SpeciesFilter` and `DetectionSession`), and each one gets unit tests (`swift test --package-path apps/ios/OverheardKit`). Quality changes are measured with `overheard-eval`. Once there's real app logic (walk flow, SwiftData, UI state), add tests for it too.
- **Branches and PRs:** never commit to `main`. Each body of work gets a branch off an up-to-date `main` (`feat/…`, `fix/…`, `ci/…`, `docs/…`), and you push it and open a pull request. CI runs on every PR and on `main`.
- **Commits:** small and descriptive. Update `todo.md`, `docs/decisions.md` and this file in the same commit when they change.

## Gotchas

- **BirdNET audio model:** input `inputs` is [1, 144000] Float32 (3 s at 48 kHz mono). Output `Identity` is [1, 6522] logits. Confidence is `sigmoid(clip(x, -15, 15))`.
- **BirdNET location model:** input `location` is [1, 3]: latitude, longitude, week. Output `Identity` is [1, 6522] occurrence values, 0–1, and "expected here" means occurrence ≥ 0.03.
  - It's a rebuild of the original (`convert.py`'s `meta_function`), because the original encoding layer doesn't convert. The rebuild matches the original within 2e-5.
- **BirdNET weeks** run 1–48, four per month: `week = (month-1)*4 + min(4, (day-1)/7 + 1)`. Week -1 means "all year".
- **Species splits:** for the 32 BirdNET species eBird has since split, `species.json` keeps BirdNET's concept (name plus group code) and lists the daughters in `split` (`Species.splitInto`). Don't map them to a daughter by scientific name; `BundledCatalogTests` guards this.
- **Labels:** `labels.txt` lines look like `Scientific name_Common name`, where line index = output index. 101 labels aren't birds (sounds, frogs, insects, mammals). One pair of labels shares a code because eBird has since lumped the two species.
- **Saving walks:** iOS can kill the app mid-walk, so `WalkStore` never waits for End walk: confirmed birds save immediately, the route at least every 30 s, and everything on going to the background. At launch, open walks are closed at their last save and marked `interrupted`. `WalkBird` stores only `speciesCode`; names come from `SpeciesCatalog.species(code:)`.
- **Background location:** `UIBackgroundModes` includes `location`, and `LocationProvider` holds a `CLBackgroundActivitySession` during a walk so the route keeps recording with the screen locked.
- **Adaptive gate:** it's built and tested, but **off by default** (`ListeningPipeline.gateConfig = nil`). In the eval it skipped about half the clips but cost 2–6 points of recall in city noise. Turn it on only after measuring battery on a device.
- **FP16:** don't use it. Even with the spectrogram kept at FP32, it shifted confidences by up to ±0.17.
- **Confidence bar:** `ConfidenceBar.standard` needs base +0 for common species (≥ 10% occurrence here), +0.20 for uncommon (≥ 3%), and +0.40 for unusual (≥ 1%), capped at 0.95. Rarer species are hidden. A rare bird's single-clip confirmation must also clear its bar by 0.15. On the rare-bird eval set it reports 70% of real unlikely-here birds, where the old cutoff reported 0%.
- **Audio session:** use `.record` with `.measurement` mode. Other modes apply voice processing that suppresses birdsong.
- **Free signing:** builds expire after 7 days. The first install needs Settings → General → VPN & Device Management → Verify App; if that fails, try cellular instead of Wi-Fi.
- **LFS bandwidth:** GitHub's free LFS tier allows 1 GB a month. CI caches `.git/lfs`, but avoid re-committing the models needlessly; each version adds about 100 MB.
- **Gemini images:** they come back as JPEG, even when saved as `.png`.
- **Fonts:** the app bundles static weights (EB Garamond and Caveat are instanced from Google's variable fonts with fontTools). `Font.display/smallCaps/body/hand` use PostScript names like `IM_FELL_English_Roman`; a wrong name silently falls back to the system font.
- **Demo walk:** Debug builds launched with `-demo` (a scheme argument, off by default) open on a sample walk, and a robin arrives 3 s in. Use it for screenshots and design work; it never touches the walk store.
- **Tuning the page:** every journal-page setting is in `OverheardKit/Page/PageStyle.swift` (`PageStyle.standard`). Debug builds have Me → Field-test tools → Page tuning: sliders over a live sample page, applied app-wide, kept across launches, with "Copy as code" to paste back into `standard`.
- **Bird art files** are named by species code (`art/birds/cutouts/<code>.png`), so split species use their group code (House Wren is `y01309`). Cut out with `cutout.swift`, which defringes edges; a plain mask leaves a white halo on the darker Candlelight page.
- **CI's Swift is older than a current Mac's:** CI runs `macos-15`'s default Xcode, while a local Xcode may be newer and accept code CI rejects (e.g. a `CGFloat` going into a `Double` tuple without `Double(...)`). Watch the PR's CI run, not just the local build.
- **Shell noise:** the user's shell prints `_encode`/`_decode` noise from gvm on `cd`. It's harmless.

## Settled decisions (don't redo without new evidence)

These were tried and measured. Reasons are in `docs/decisions.md`, numbers in `ml/eval/README.md`.

- FP32 models, not FP16.
- Base threshold 0.50 ("fewer wrong birds"), not 0.35.
- Confirmation: 2 clips or one clip ≥ max(0.70, bar + 0.15).
- Steep confidence bar (+0.20 / +0.40), not gentler tiers.
- Adaptive gate off until battery is measured on a device.
- A 3 s clip every 1 s; "×count" means separate songs (≤ 2.5 s apart merge).
- Species are stored by code. Split species keep BirdNET's concept.

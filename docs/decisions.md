# Decisions

A dated log of what we decided and why. Newest at the bottom. To change a decision, add a new entry rather than editing an old one.

## 2026-10-18

- **Product:** an iPhone app that listens during **walks** (not all day from a window) and turns each walk into an illustrated journal page.
  - *Why:* Manhattan window audio is noisy and has few species. Central Park is a migration hotspot. Walk sessions also avoid iOS background-recording and battery problems.
- **Name:** *Overheard: Bird Journal*. **Domain:** `overheardbirds.app`, registered with Cloudflare.
- **Monetization:** none. The app is free, for friends and family.
  - *Why:* BirdNET is CC BY-NC-SA 4.0, which is fine for non-commercial use with attribution.
- **Distribution:** TestFlight first. The public App Store later, through full App Review.
- **Bird ID:** BirdNET, run on the device with Core ML, using its location/week filter. Audio never leaves the phone.
- **Platform:** iOS 17+ with SwiftUI and SwiftData.
- **Backend:** Cloudflare (Workers, D1, R2, Queues), managed with Terraform.
  - *Why:* about $5/month, no egress fees on images, and much less infrastructure than AWS.
  - *Rejected:* AWS (more cost and setup), and Go on Workers (only through WebAssembly, so second-class).
- **Language:** TypeScript, using **Hono** for the API and **Drizzle** for the ORM on D1.
- **Monorepo:** pnpm workspaces, no Turborepo. Layout is in `CLAUDE.md`.
- **API contract:** an OpenAPI spec generated from zod schemas, then turned into a Swift client by `swift-openapi-generator`. Swagger/Scalar is served at `/docs`. Endpoints are listed in `docs/api.md`.
- **Auth:** Sign in with Apple only. The Worker verifies Apple identity tokens itself, with no hosted auth service.
  - *Why:* Apple requires Sign in with Apple whenever Google sign-in is offered, and it needs the least setup.
- **Images:** files live in R2, and D1 stores only their keys. Uploads go through the Worker.
- **Location privacy:**
  - Shared locations snap to a ~500 m grid.
  - Walk routes are trimmed ~200 m at the start and end.
  - Sensitive species (owls, etc.) show no location to others.
- **Observability:**
  - Workers traces are exported over OTLP to **Honeycomb**.
  - All errors, from iOS and every Worker, go to **Sentry**.
  - No local traces. Local dev logs print to the terminal.
- **Local dev:** `wrangler dev`, with no Docker. A dev-only fake image service and a dev login bypass.
- **Image model:** `gemini-3-pro-image` through the **Batch API** (~$0.067 per image).
  - *Why:* in the trial (`art/model-comparison/`), Pro had the best field-journal style and the best variations. OpenAI models gave transparency, but with halos and a digital-painting look.
- **Art pipeline:** generate on flat white, then remove the background to get a transparent PNG, then composite onto the parchment page.
- **Look:** a hand-drawn field journal on parchment, applied to the whole app. The dark mode is **"By Candlelight"**. Details are in `docs/design.md`.
- **Page rules:**
  - Bird size reflects call count on Listen and Journal pages; Flock cards use even sizes.
  - Rare birds get a red-ink "naturalist flourish" rather than a bigger size.
- **BirdNET on iOS:** the v2.4 SavedModel is converted to Core ML with coremltools. A custom `Cast` rule handles the complex STFT. The result matches TensorFlow on all 40 test clips. The location model doesn't convert yet, so we bundle a precomputed per-week species table (Central Park for now). See `ml/README.md`.
- **Xcode project:** generated by **XcodeGen** from `apps/ios/project.yml`. The `.xcodeproj` is gitignored.
  - *Why:* no hand-merged `.pbxproj` files.
- **Spike result (iPhone 17 Pro):** BirdNET Core ML inference takes about **21 ms per 3 s clip**. Birdsong played from YouTube was detected at 85–94% confidence. That's fast enough to use overlapping windows later.
- **Testing approach:**
  - Pipeline and app logic live in `apps/ios/OverheardKit` as plain, model-free types with unit tests (`swift test`).
  - Detection quality is measured with the `overheard-eval` harness, which runs the same Swift code on the Mac.
  - App-level logic (walk flow, SwiftData, UI state) gets tests once it exists.
  - *Why:* the user wants tests once there's real logic and interactivity, and putting the logic in the package makes that cheap.
- **Non-bird labels:** BirdNET's 101 non-bird classes (sounds, frogs, insects, mammals) are never reported. They're identified by matching against the eBird taxonomy (`ml/bird_labels.py`).

## 2026-10-18 (architecture review)

- **Location filter works anywhere.**
  - BirdNET's location model runs on the phone as Core ML. `convert.py` rebuilds its input-encoding layer so it converts, and the rebuild matches the original within 2e-5.
  - The app uses approximate location: once at start, again after a ~10 km move or a new week. Without location permission it falls back to no location filter, with non-birds still blocked.
  - Occurrence scores are kept for rarity later.
  - *Replaces* the precomputed Central Park table.
- **Species are identified by stable codes:** eBird species codes (`norcar`), or `birdnet:<scientific>` for 32 renamed birds. They come from `species.json`, which `bird_labels.py` builds. Model indices never leave the classifier.
  - *Why:* indices change between BirdNET versions. Saved walks, life lists, the backend and art all need a stable key.
- **Pipeline as an actor:** `ListeningPipeline` (OverheardKit) owns the models, the location state and `DetectionSession`. The UI only sends clips and receives updates. **Swift 6 strict concurrency** is on for the app and the package.
- **Models stay FP32.** FP16, even mixed with the spectrogram at FP32, shifted confidences by up to ±0.17 to save about 35 MB. The app is about 104 MB.
- **Built models live in Git LFS** (`ml/models/coreml`), with CC BY-NC-SA attribution. A fresh clone and CI build without TensorFlow. CI caches LFS objects to stay under GitHub's 1 GB/month free bandwidth.
  - *Replaces:* "model files are gitignored."
- **CI:** GitHub Actions runs OverheardKit tests, an unsigned iOS build (macOS 15 runner), and Ruff.
- **Signing:** the team ID lives in gitignored `apps/ios/Config/Local.xcconfig`, not in `project.yml`.

## 2026-10-18 (detection step 3)

- **"×count" means separate songs or bursts of calls,** not minutes present or separate visits. Each song counts once, and bird size grows on a capped log scale so a nonstop singer doesn't dominate the page.
- **Overlapping clips:** a 3 s clip every **1 s**, and detections of a species ≤ 2.5 s apart are one call. In the eval, recall rose 4–9 points (most in city noise) and precision fell 3–5. Step 4's confirmation rule is meant to win that back.

## 2026-10-18 (detection step 4)

- **Call confirmation:** a call counts only once it has **≥ 2 clips above the threshold, or one clip ≥ 0.70**. Until then, a new species is *pending*.
  - In the UI, a pending bird is the faint **"sketching" bird**. It finishes drawing when confirmed and fades if the call ends unconfirmed.
  - Later calls of an already-confirmed species need confirming too, so counts don't inflate.
- **Operating point:** threshold **0.50** with that confirmation ("option B: fewer wrong birds"). In the eval, wrong species per recording halved (0.32 → 0.15), precision went 72.9% → 83.7%, and recall went 85.5% → 79.1%. The alternative was 0.35 for 83.6% recall and 78.6% precision.
  - *Why:* a wrong bird drawn on a shared journal page is worse than a missed one, and pending birds still show up as sketches.

## 2026-10-18 (detection step 5)

- **Likelihood-scaled confidence bar** (`ConfidenceBar`) replaces the hard "expected (≥ 3%) or hidden" cutoff. Common species need the base threshold (0.50); **uncommon (3–10%) need +0.20; unusual (1–3%) need +0.40**; species under 1% are hidden. Required confidence is capped at 0.95.
  - Rare birds also need stronger confirmation: one clip must clear its own bar by 0.15, otherwise 2 clips are needed.
  - *Why steep:* of the tiers tried, it's the only one that beat the old cutoff on precision (84.3% vs 83.7%, and 87.5% vs 85.7% in city noise), at the cost of 1 recording of recall. It still lets clearly heard rare birds through.
  - *Caveat:* the eval set has no rare targets, so the rare-bird upside is unmeasured. A rare-bird eval set is next (todo step 5b).
- **`Commonness`** (common / uncommon / unusual) travels with every score, pending bird and heard bird. It's the single source for the rare-bird flourish, sketch styling and life-list badges.
